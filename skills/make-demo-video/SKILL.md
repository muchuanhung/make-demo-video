# make-demo-video

把素材變成一支 10–40 秒、有字幕的 demo 影片；放 README 的預設是 12–20 秒的快節奏短片。影片不是錄螢幕，而是 **剪法（cut）** 排出一份 **分鏡表（storyboard.json）**，再套 **一份風格（style）** 算出來的：

- 剪法決定怎麼剪（腳本寫法、鏡頭順序、節奏），風格決定長什麼樣（顏色、字體）。

- 改一句字幕，只要改 JSON 再算一次，大約 20 秒。
- 分鏡表是純文字，可以 commit、diff、code review。

## 開始前

第一次使用時，在本 skill 的資料夾裝相依套件（之後不用再裝）：

```bash
cd <本 skill 的資料夾> && [ -d node_modules ] || npm install --no-fund --no-audit
```

需要 Node 18 以上與 Google Chrome（沒有 Chrome 時改跑 `npx playwright install chromium`）。ffmpeg 已隨套件附上，不用另外裝。

**執行時不要修改 skill 本身**：`<skill>/` 底下的檔案（`player/`、`scripts/`、`cuts/`、`styles/`、`SKILL.md`）一律不改、不 commit，只寫輸出資料夾。影片要的效果現有的鏡頭模板或欄位做不到時，停下來告訴使用者「哪一幕、想要什麼效果、現在做不到的原因」，建議改用做得到的寫法，或到本專案開 issue；不要自己改播放器或檢查來繞過。

以下 `<skill>` 代表本 skill 的資料夾，`<out>` 代表輸出資料夾。輸出資料夾預設放在使用者目前所在專案的 `docs/demo/`；目前不在任何專案裡時，問使用者要放哪裡。

## 四步流程

照順序做。使用者常常是在旁邊看著終端機（甚至是台下的觀眾），所以進度要一眼看得出來：

- **四行進度一行都不能少，而且要依序各自輸出**：做完一步就輸出那一步的進度行，再開始下一步的工具呼叫。不要把四步留到最後一次總結。
  - `① 剪法`：剪法與設定選好之後、寫 `script.md` **之前**輸出。使用者在指令裡指定好、跳過提問時，**也要輸出**。
  - `② 腳本`：寫好 `script.md` 之後、寫 `storyboard.json` **之前**輸出，並把腳本逐句列出來。
  - `③ 分鏡`：寫好 `storyboard.json` 之後輸出。
  - `④ 算圖`：算圖成功之後輸出，當作最後的回覆。
- 進度行的格式是「`① 剪法｜`產出了什麼 → 一句為什麼」，下面各步有範例。
- 所有給使用者看的文字都用使用者下指令的語言，**包括工具呼叫之間的短句**；中文指令就全程用繁體中文，從第一句開始就不要夾英文。

### ① 讀素材，選剪法與設定

剪法決定腳本怎麼寫，所以**先選剪法、再寫腳本**。這一步先讀素材，再決定四件事：**剪法、比例（16:9 橫式／9:16 直式）、總秒數、幕數**。外觀不用選，一律從素材取色（見下方「從素材定義風格」）。

依素材種類讀內容：

| 素材 | 怎麼讀 |
|---|---|
| 目前所在的 repo 或本機路徑 | README、`package.json`、主要頁面與 API 的檔案，找出「這是什麼、給誰用、三個亮點」 |
| GitHub 網址 | `gh repo view <owner/repo>` 與 README；沒有 gh 就用網頁抓取 |
| 網站網址 | 網頁抓取讀文字，再截圖（見下方「網站截圖」）；抓到的只有「載入中」或空白（前端算畫面的網站）時，以截圖和錨點檔為準 |
| PDF、文章、一段文字 | 直接讀，整理成重點 |

**網站截圖**：操作示範剪法改截桌機版、一步一張（照它的 `cut.md`「截圖」）。其他剪法預設截手機版整頁長圖，給手機鏡頭在手機框裡捲動。挑 3–5 頁最能代表網站的頁面（首頁、每個主要作品或功能頁、文章、關於或聯絡），每頁用 `--name` 取不同檔名。網站只有一頁（單頁應用、功能都在首頁）時，截首頁一張就夠，之後每一句用同一張長圖捲到不同段落：

```bash
node <skill>/scripts/capture.mjs <網址> --out <out> --mobile --full --shots 0 --name home
node <skill>/scripts/capture.mjs <網址>/projects/x --out <out> --mobile --full --shots 0 --name project
```

每張長圖旁邊會一起產生錨點檔（`home-full.json`），列出頁面上每個標題與大字的位置。**截完先讀錨點檔**：分鏡表用 `to` 寫「手機捲到哪段字」，字必須是錨點檔裡有的。網站可能有深色模式時（`<meta name="color-scheme">` 不可靠，一律截圖比對），首頁再加 `--scheme dark --name home-dark` 截一張，看圖跟淺色版比對：真的變成深色才給「狀態切換」鏡頭用，看起來一樣就不排這一幕。多截的頁面沒用到也沒關係，留著就好。需要桌面版畫面時（`browser` 幕）改用 `--shots 2`、不加 `--mobile`。

錨點檔裡每一筆還有 `box`（x、y、寬、高，CSS 像素；圖上的像素要乘以檔頭的 `scale`），連結、按鈕、輸入框標 `click: true`。要截「操作之後」的畫面（展開選單、切換城市、按下按鈕）時加 `--click`，用 `>` 分開每一步，寫字就是點畫面上那段字，`type:` 是在剛點的輸入框打字：

```bash
node <skill>/scripts/capture.mjs <網址> --out <out> --full --shots 1 --name step-2 --click "切換城市 > 高雄市"
```

每次都從網址重新開始，所以第 N 步的截圖要把前 N 步都寫上。找不到那段字時會列出畫面上能點的字；操作後畫面沒變（例如搜尋框還沒接上功能），換一條路徑，不要硬截。

`<out>` 裡已經有截圖（`shot-*.png` 或其他 `.png`、`.jpg`）時直接沿用，不要重新截圖。例外：要做 9:16 但現有截圖是橫的（寬大於高），放進直式畫面會很小，先告訴使用者，再用 `--mobile` 另外截一組（使用者可能先備好畫面，避開網路不穩或線上資料空白）。截圖後先看圖；畫面上的數字是 `--`、空白或載入中時，告訴使用者，不要把那一塊當成推近重點。

**挑推薦的剪法**：讀 `<skill>/cuts/*/meta.json`（見「剪法」），依 `suits`、`needs` 和素材挑最合適的 1–3 包，最合適的放第一個，並用一句話說明理由。理由要寫到這次的素材（例如「天氣網站截圖完整、單頁就有五個功能，適合手機捲動導覽」），不要只重述剪法的說明。

**生成式剪法**（`meta.json` 有 `"mode": "generate"`，例如招牌片 `signature`）不用鏡頭模板，畫面每次由你從零寫，從讀素材到出片約 10 分鐘。推薦它時，理由後面要加上「生成較久、每次結果不同」；它不看幕數，面板或提問裡的幕數照預設送出即可。

**已經備好腳本時**（見 ② 的條件），幕數預設為腳本句數；剪法仍然要選，它決定每句配哪個鏡頭，但不改腳本的字。

使用者已經在指令裡指定的項目就不再問；剪法、比例、秒數都指定了時跳過提問，直接輸出進度行。

**有 `mcp__make-demo-video__show_options` 工具時**（make-demo-video 面板已載入），用面板問：

1. 呼叫它，傳 `out`（輸出資料夾）、`cuts`（推薦的剪法 id，最合適的放第一個）、`reason`（推薦第一個的理由）、`scenes`（建議幕數）、`seconds`（建議總秒數，不給就用剪法的預設）。
2. 輸出進度行 `① 剪法｜請在右側面板選擇剪法、比例、秒數與幕數`，然後**結束這一回合**，不要再呼叫工具，也還不要寫腳本。
3. 使用者按「確定」後，下一則訊息會是 `① 選好了：剪法 …、比例 …、約 … 秒、… 幕`，照它繼續。

**沒有這個工具時**，用 AskUserQuestion 一次問完（同一次呼叫，最多四題）：

| 題目 | 形式 |
|---|---|
| 剪法 | 選項題：推薦的剪法，第一個標「(Recommended)」；`description` 寫推薦理由，`preview` 放 `suits` 與鏡頭順序。**只有一包剪法時不問這題**，直接用它 |
| 比例 | 選項題：「16:9 橫式（README、簡報）」「9:16 直式（社群短影音）」 |
| 秒數 | 數字題 `kind: "number"`，`min: 10`、`max: 60`、`step: 5`、`unit: "秒"`，預設為剪法 `defaults.seconds` |
| 幕數 | 數字題 `kind: "number"`，`min: 3`、`max: 12`、`unit: "幕"`，預設照剪法與秒數推算（已備好腳本時是腳本句數）；只推薦生成式剪法時不問這題 |

這個版本的 AskUserQuestion 不支援數字題時，秒數改成選項題（12／20／30／45 秒），幕數改成選項題（建議幕數、少一幕、多一幕）。

**從素材定義風格**：每支影片都要做（生成式剪法例外：顏色與字型直接寫進 `reel.html`，不寫 `style.json`）。從素材裡取色與氣氛（網站的主色與字體、品牌色、使用者提供的圖片或描述；素材沒有品牌色時，照內容的氣氛自己配一組，並說明理由），照「風格檔格式」寫一份 `<out>/style.json`，告訴使用者取了哪幾個顏色、從哪裡取的。文字與底色的對比要夠（深底配淺字或反過來），`accentText` 要能在 `accent` 色塊上讀得清楚；`accentInk` 是重點色當「字」用時的顏色：快節奏風格的重點字都是大標題，直接用品牌色本身就好（大字對比 2.5 以上就看得清楚）；只有品牌色在底色上幾乎看不見（例如淺黃配白底）時，才換成較深的同色系。要做出快節奏的質感，自訂風格從這份範本改顏色與字體（欄位說明見「風格檔格式」）：

```json
{
  "id": "site-name", "name": "網站名稱", "description": "取自哪裡、什麼氣氛",
  "colors": { "bg": "淺色底", "surface": "卡片色", "text": "近黑字", "muted": "灰字", "accent": "品牌色",
              "accentText": "品牌色色塊上的字", "accentInk": "通常同 accent", "border": "線條色", "invertBg": "深色模式的底" },
  "fonts": { "display": "\"網站字體\", \"PingFang TC\", sans-serif", "body": "\"網站字體\", \"PingFang TC\", sans-serif", "mono": "Menlo, \"PingFang TC\", monospace" },
  "fontUrl": "（網站用 Google Fonts 時）",
  "radius": 22, "shadow": "0 12px 32px rgb(0 0 0 / 0.10)",
  "motion": { "enter": "rise", "heading": "blur", "duration": 0.4, "transition": "cut" },
  "decor": "halo", "mark": "ink", "align": "left", "progress": false, "caption": "plain"
}
```

幾個欄位的意思：

- `motion`：`{ "enter": "rise", "heading": "blur", "duration": 0.4, "transition": "cut" }`，標題 0.16 秒內由模糊彈成清楚、之後不動；幕與幕之間直接切，特別的轉場寫在分鏡表的各幕。
- `decor: "halo"`（格線＋會動的重點色光暈）、`mark: "ink"`（重點字只換顏色）、`align: "left"`（大標題靠左）、`progress: false`。
- 網站有深色模式時，`invertBg` 取深色模式的底色；沒有深色模式就不寫（會用 `text` 的近黑色）。
- 網站用系統字體時，`fonts` 寫 `"system-ui, -apple-system, \"PingFang TC\", \"Noto Sans TC\", sans-serif"`、不寫 `fontUrl`。
- 網站用 Google Fonts（例如 `next/font/google` 的 `Noto_Sans_TC`、或 `<link href="https://fonts.googleapis.com/...">`）時，`fontUrl` 填同一套字的 Google Fonts CSS 網址（含 700、900 字重），`fonts` 第一個寫那個字體名稱。

選定後先寫好 `<out>/style.json`，再輸出進度行，例如 `① 剪法｜fast-tour 快節奏導覽・16:9・15 秒・6 幕 → 天氣網站截圖完整，適合捲動導覽`，並在後面說明取了哪幾個顏色、從哪裡取的。

### ② 寫腳本

腳本一定要寫成檔案 `<out>/script.md`：一句一行、前面編號，一句對應一幕，句數等於 ① 選的幕數（生成式剪法照它 `cut.md` 的句數，不看幕數）。之後排分鏡照這份檔案走，使用者想改文案時改這份就好。

**使用者已經備好腳本時，直接沿用，不要改寫。** 符合下面任一種就算備好了：

- `<out>/script.md` 已經存在。
- 使用者在指令裡給了一個腳本檔（一句一行、或有編號的條列），或說「用這份腳本」。

沿用時，把內容原樣寫進 `<out>/script.md`（已經在那裡就不用動）。素材仍然要讀，用來截圖、找畫面，但不改腳本的字；有句子超過 20 字或寫了素材裡讀不到的事，在進度行後面提醒使用者，由他決定要不要改。

**沒有備好腳本時**，照 ① 選的剪法 `cut.md` 的「腳本」一節寫。不論哪個剪法都要守的原則：

- 本 repo 的範例（`examples/`）只用來看結構和排法，腳本要照你讀到的素材寫；素材剛好是範例的同一個網站時也不要照抄。
- 只寫素材裡讀得到的事實，不要編數字或功能。

`script.md` 寫好（或確認沿用）之後輸出進度行，把腳本逐句列出來：

```text
② 腳本｜docs/demo/script.md，6 句 → 照 fast-tour 寫，只寫 README 和程式裡讀得到的事實
  1. 台灣天氣，一頁看完
  2. 選縣市，看現在天氣與日出日落
  …
```

沿用時改成 `② 腳本｜docs/demo/script.md，6 句 → 沿用你備好的腳本，一字不改`。

### ③ 排分鏡

**① 選的是生成式剪法時**（`meta.json` 有 `"mode": "generate"`），③ ④ 改照該包 `cut.md` 的「概念」「逐拍」「做法」「檢查與修改」走：不寫 `storyboard.json`、不跑 `frames.mjs` 與 `render.mjs`，改寫 `<out>/beats.md` 與 `<out>/reel.html`，用 `signature.mjs` 檢查與算圖。

- **有 `mcp__make-demo-video__show_concepts` 工具時**（面板已載入）：腳本寫好後呼叫它給三個概念（第一個是你推薦的），輸出 `③ 概念｜請在右側面板挑一個概念` 就結束這一回合；使用者挑好後下一則訊息是 `③ 概念選好了：…`。`signature.mjs beats` 檢查通過後，面板會自己讀 `beats/beats.json` 畫逐拍分鏡板（一小節一排，每拍可以留意見），所以輸出 `③ 逐拍｜…` 就結束這一回合，**不要自己跑 `render`**，等使用者按「合成影片」。
- **沒有這個工具時**：概念用 AskUserQuestion 問；每拍縮圖（`beats-sheet.png`）在對話裡給使用者看：先用 Read 看過，再請使用者說要改哪幾拍。

進度行：

```text
③ 概念｜一個點，長成一頓飯（三選一，你選了第 1 個）
③ 逐拍｜docs/demo/reel.html，30 拍，檢查通過 → 在面板上每拍按 ✎ 留意見，可以了按「合成影片」（沒有面板時：要改哪幾拍？說「第 N 拍：…」，可以的話說「算圖」）
④ 算圖｜docs/demo/demo.mp4、demo.gif，15 秒、60fps、有配樂 → 結果頁已打開
```

以下是鏡頭模板剪法的做法。

**動手寫 `storyboard.json` 之前先檢查**：`<out>/script.md` 寫好了嗎？這次對話裡已經輸出過 `① 剪法｜…` 和 `② 腳本｜…`（含逐句腳本）兩行了嗎？還沒有的話，現在先補，再寫分鏡表。

分鏡由**鏡頭模板**組成：每一句腳本挑一個模板（下表）、填上字和截圖。模板已經包好底色、文字效果、轉場、手機怎麼捲，不要自己用低階參數拼。**哪句配哪個模板、順序、拍數怎麼分，照 ① 選的剪法 `cut.md`**；只能用該包 `meta.json` 的 `shots` 列出的模板。照下面三步做：

**1. 先在回覆裡列鏡頭表**（給使用者看，也是排分鏡的依據）：

```text
| # | 腳本 | 鏡頭 | 畫面證據（截圖：錨點） | 拍 |
|---|---|---|---|---|
| 1 | 把想法做成真的。 | hook | — | 3 |
| 2 | 洪睦筌 | intro | home-dark-full.png：先停在「把想法」，捲到「做過一些有意思的事」 | 5 |
| 3 | 曉行 Dawnline | card | — | 3 |
| 4 | 切換深色／淺色模式 | toggle | home-dark-full.png → home-full.png | 4 |
| 5 | 出發前，判讀路線風險 | feature | project-full.png：捲到「技術」 | 5 |
```

- **畫面證據**：手機鏡頭（intro、feature、content、cta）一定要寫截圖和錨點，錨點是錨點檔裡講這句話的那段字；找不到能證明這句話的畫面時，換一句、補截圖，或改用 card。
- **秒數與幕數**：總長對準 ① 選的秒數，幕數等於 ① 選的幕數，和句數不同時先改 `script.md` 並告訴使用者改了哪幾句。拍數怎麼分、相鄰兩幕怎麼避開重複，照剪法 `cut.md`。
- 分鏡表最上層寫 `"cut": "<剪法 id>"`，記下這支片用哪個剪法排的（算圖不看它，之後重排或改選時照同一包）。

| 鏡頭 | 用在 | 必填 | 選填 | 預設拍 | 模板自動做的事 |
|---|---|---|---|---|---|
| `hook` | 第一句、標語 | heading | kicker | 3 | 滿版重點色；兩行字一行一行彈出 |
| `intro` | 名字、產品名第一次出現 | heading、image | kicker、to、from | 5 | 深色底；手機從下方升起，從上一句出現的位置慢慢開始捲（跨鏡頭銜接；截圖上找不到上一句就從頁首開始），後半捲到 `to` |
| `card` | 作品、方案這類清單的每一項（沒有畫面也講得清楚的） | heading | label、icon、year（沒有年份就不寫）、kicker、align（`center` 時卡片與字整組置中） | 3 | 手機後面接時往鏡頭衝（zoom）、卡接卡閃白（flash）；底色深色、橘色輪流；標題保證停得夠久 |
| `toggle` | 狀態切換（深色／淺色、修改前後） | heading、image、after | pill、to | 4 | 前 40% 是 image（深色底），斜切成 after（淺色底），字不重新進場 |
| `feature` | 一個作品或功能的細節 | heading、image | kicker、tags、to | 5 | 前一幕糊掉、手機從右邊滑入，標籤一個個彈出，捲到 `to` |
| `content` | 文章、說明、內容列表 | heading、image | to | 4 | 深色底、手機在另一側，捲到 `to` |
| `cta` | 號召行動（聯絡、試用、下載）；單頁網站沒有號召行動時，給最後一個功能當特寫 | heading、image | to | 3 | 手機特寫（放大、下緣出畫面），很快捲到 `to` 停住 |
| `stat` | 一個數字（使用者數、評分、地點數），只用素材裡讀得到的數字 | heading（數字下面那行說明）、value（例如 `1,534`、`6,000+`、`96.8%`） | kicker、start（從多少開始跳，預設 0） | 4 | 深色底；數字 0.9 秒內前快後慢跳到 value，千分位與小數位照 value 的寫法，底下一條線跟著長出來；最後一格一定等於 value |
| `outro` | 最後一句 | heading | kicker、sub、url | 5 | 從畫面上一點展開成重點色，名字彈進來，網址膠囊（沒寫 url 時用分鏡表最上層的 url）；不放 QR code |

- 錨點只收標題、大字、粗體短標籤和輸入框提示文字，不收純數字（氣溫、價格會變）。要的字不在錨點檔裡時，改用旁邊的區塊標題當 `to`。
- `heading` 放腳本原句，可以加 `\n` 分兩行、`**粗體**` 換成重點色，不改字。`kicker` 是標題上方的小字，`tags` 是 3–6 個 1–3 字的關鍵字，`pill` 是膠囊標籤。小標與標籤是點綴，不是第二句話：標題已經是一整句時，小標、標籤擇一或都不放（標題加小標、標籤超過 16 字會被提醒）；名字、作品名這種短標題才配技術標籤。
- `to`、`from` 寫錨點檔裡的字（部分符合就行），`from` 只在想指定手機從哪裡開始時才寫。
- 需要時可以覆寫：`beats`、`tone`（base、invert、accent）、`transition`、`layout`、`textFx`（blur、rise）。沒有特別理由就用模板預設；自動檢查提醒「太像」時才換 `layout`。`layout` 三種：`right` 字在一側、手機在另一側（直式是字在上、手機在下）；`left` 左右對調（直式是手機在上、字在下）；`big` 手機放大、下緣出畫面的特寫，字壓在上方。手機鏡頭另可寫 `phoneScale`（0.4–1.2，預設 1）等比例縮放這一幕的手機，例如直式畫面裡手機下緣被切到、想整台露出來時寫 0.8。
- 素材不是網站（CLI、程式碼、純文字）時，可以混用舊的低階幕別（見「分鏡表格式」最後），但能用模板的句子就用模板。

**2. 寫 `<out>/storyboard.json`**：照鏡頭表寫（格式見下）。

**3. 跑自動檢查，修到沒有提醒**：

```bash
node <skill>/scripts/check.mjs --storyboard <out>/storyboard.json
```

它會檢查：錨點找不到（錯誤，會列出截圖裡有的字）、標題出完停不夠久（照字數算：至少 0.5 秒，每個字 0.06 秒，12 字 0.72 秒；小標、標籤算一半；提醒會說要加幾拍）、一幕字太多（標題超過 16 字，或標題加小標、標籤超過 16 字）、相鄰兩幕太像、手機畫面沒對上這句話、單幕太長、同一種底色連太多幕、平均鏡頭太慢。有錯誤或提醒就改分鏡表再跑，直到「自動檢查沒有提醒」。真的改不掉的提醒（例如使用者指定的秒數讓平均變慢），在 ③ 進度行後面說明原因。

檢查通過後輸出進度行，例如 `③ 分鏡｜docs/demo/storyboard.json，9 幕 12 秒 → 開場標語、介紹、兩張作品卡、深淺切換、功能、文章、號召、結尾；自動檢查沒有提醒`。

**① 是用面板問的時候**（呼叫 `show_options` 成功），輸出 ③ 進度行後就**結束這一回合**：面板會自己產生每一幕的縮圖（分鏡板），讓使用者確認、調整，按「合成影片」後才進 ④。不要自己跑 `frames.mjs` 或 `render.mjs`。

**沒有面板時**，直接進 ④。

### ④ 算圖輸出

```bash
node <skill>/scripts/render.mjs --storyboard <out>/storyboard.json --style <風格 id 或 style.json 的路徑> --out <out>
```

預設每秒 30 格、沒有聲音。使用者要配樂或要更順的動態時加這兩個參數（只影響 MP4，GIF 本來就沒有聲音）：

- `--music`：照節拍與每一句的起點合成配樂，每拍一個大鼓、換句時一記重拍、最後一句前四拍一段上升音；同一份分鏡表每次算出一樣的聲音。有 `burst`（操作示範的重拍）時，上升音改接到 burst 的第一拍（drop：前兩拍抽掉大鼓、落下更重的一記加低音），burst 裡每一張截圖的硬切各一記重拍。
- `--motion-blur 6`：每格拍 6 張再平均，快速移動會拖出模糊；子格不跨過換幕，硬切不會疊影。算圖時間約變成 3–4 倍。

GIF 預設橫式 640 寬、直式 360 寬、每秒 12 格；超過 5 MB 時 render.mjs 會提醒，照它給的參數重跑就好。完成後會印出 MP4、GIF、結果頁的路徑，並在 macOS 上自動打開結果頁。算圖成功就直接回報，不要再抽格、截圖或讀影片檢查（render.mjs 已經驗過分鏡表，使用者正在看結果頁）。最後的回覆保持短，前三步已經講過的不要重複：

```text
④ 算圖｜docs/demo/demo.mp4、demo.gif，13.6 秒 → 結果頁已打開（加了 --no-open 時改寫結果頁的路徑）
README：[![demo](docs/demo/demo.gif)](<網址>)
想改就說，例如「第三幕字幕改短」「第五幕換一張截圖」，改完重跑同一行指令即可。
```

算圖失敗時，錯誤訊息會指出哪一幕的哪個欄位有問題，修正分鏡表後重跑；不要改 `player/` 或 `scripts/` 來繞過檢查（見「開始前」）。

### 面板送來的訊息

使用者在面板上按的按鈕，會變成一則以固定字樣開頭的訊息。面板上的上移、下移、刪除、改字、秒數 − ＋（改 `beats`，沒有模板的幕改 `seconds`），都已經直接改好檔案，不會送訊息；之後重排或重畫時，沿用使用者調過的拍數與秒數，不要改回模板預設；使用者把某一幕拉到超過 3 秒造成的「太長」提醒是使用者的選擇，不用為了消提醒改回去，在 ③ 進度行說明即可。

| 訊息開頭 | 怎麼做 | 做完 |
|---|---|---|
| `合成影片：…用風格 X 算圖`（舊版是 `重新算圖：`） | 分鏡板已經是使用者要的樣子：**不要改 `storyboard.json` 或 `script.md`**，用訊息裡的風格 X 跑 ④ 的算圖指令（使用者可能在面板上換過風格，以訊息為準） | 輸出 `④ 算圖｜…` |
| `① 選好了：…` | 照選的剪法與設定做：先從素材寫 `style.json`，輸出 `① 剪法｜…`，再照剪法寫腳本（②）、排分鏡（③） | 依序輸出 `① 剪法｜…`、`② 腳本｜…`、`③ 分鏡｜…`，結束這一回合 |
| `① 改選：…（原本剪法 …）；照新剪法重寫…` | 使用者換了剪法：照新剪法的 `cut.md` 重寫 `script.md`（使用者備好的腳本不改字，只照新剪法重配鏡頭），再重排 `storyboard.json`，`cut` 改成新剪法 | 輸出 `① 剪法｜…`、`② 腳本｜…`、`③ 分鏡｜…`，結束這一回合 |
| `① 改選：…（原本 …）；照新設定重排…` | 使用者改了比例、秒數或幕數：照 ③ 重排 `storyboard.json`（9:16 要手機截圖、秒數與幕數對準、句數不同時調整 `script.md` 並告知）；句子沒變的幕盡量沿用原本的畫面 | 輸出 `① 剪法｜…`、`③ 分鏡｜…`，結束這一回合 |
| `照腳本重排：` | `script.md` 是使用者要的腳本，**不改它的字**。照 ③ 的規則一句一幕重寫 `storyboard.json`：句子沒變的幕沿用原本的畫面、推近與點擊，新的句子補上合適的畫面；剪法、比例、風格不變，總秒數維持 ① 選的長度 | 輸出 `③ 分鏡｜…`，結束這一回合 |
| `插入一幕：在第 N 幕後面插入一句「…」` | 在第 N 幕後面插一幕給這句：挑合適的鏡頭模板與截圖，`heading` 用這句原文；**其他幕的畫面與字幕不動**，必要時微調其他幕秒數讓總長維持 ① 選的長度。訊息註明「script.md 已更新」就不要再改腳本，沒註明就把這句插進 `script.md` 同一個位置 | 輸出 `③ 分鏡｜…`，結束這一回合 |
| `③ 概念選好了：…`（招牌片） | 照選的概念寫 `beats.md` 與 `reel.html`，跑 `signature.mjs beats` 直到檢查通過（見 `cut.md`）。訊息是「你來決定」時，從 `show_concepts` 給的概念挑最適合的，回覆裡說挑了哪個 | 輸出 `③ 概念｜…`、`③ 逐拍｜…`，結束這一回合 |
| `改第 N 拍（t 秒）：…`（招牌片） | **只改 `reel.html` 裡第 N 拍那段**，其他拍不動；改完重跑 `signature.mjs beats` 直到檢查通過，面板會更新縮圖 | 輸出 `③ 逐拍｜…`，結束這一回合 |
| `合成影片：逐拍分鏡板確認好了，照目前的 reel.html 算圖`（招牌片） | 不要改 `reel.html`，直接跑 `signature.mjs render <out>/reel.html`；它會產生 `demo.html` 結果頁並打開 | 輸出 `④ 算圖｜…` |
| `① 改選：…；概念不變，照新設定改寫 reel.html`（招牌片） | 使用者改了比例或秒數：概念與腳本不變，照 `cut.md` 調整 `SIGNATURE` 的尺寸、長度與各拍時間，重跑 `signature.mjs beats` | 輸出 `① 剪法｜…`、`③ 逐拍｜…`，結束這一回合 |
| `重畫第 N 幕：…` | 照冒號後的要求只改第 N 幕的畫面（`shot`、`image`、`to`、拍數等），`heading` 維持腳本原句；**其他幕不動**。要求是「換一個呈現方式」時，換一種鏡頭模板或換一頁截圖。改完跑 `check.mjs` | 輸出 `③ 分鏡｜…`，結束這一回合 |

改完分鏡表就停下來，面板會重算縮圖，等使用者再按「合成影片」。

### 其他指令

- **同一份分鏡表出多種風格的合輯**（開場或比較風格用）：
  `node <skill>/scripts/reel.mjs --storyboard <out>/storyboard.json --styles screenplay,terminal,neon --from 1 --seconds 5`
- **多個專案 × 多種風格的合輯**：寫一份 `reel.json` 列出每一段，再跑 `node <skill>/scripts/reel.mjs --plan reel.json`。
  `{ "seconds": 5, "clips": [{ "storyboard": "../a/storyboard.json", "style": "neon", "from": 3 }] }`，路徑相對於 reel.json，`style` 可以是內建 id 或風格檔路徑。
- **不算圖先預覽**：用瀏覽器打開 `<out>/demo.player.html`，會循環播放。

## 剪法

剪法（cut）決定影片「怎麼剪」：腳本寫法、鏡頭順序、節奏。每包是 `<skill>/cuts/<id>/` 一個資料夾：

- `meta.json`：`id`、`name`、`description`、`suits`（適合什麼素材與用途）、`needs`（需要什麼素材）、`defaults`（預設比例、秒數、`beat`）、`shots`（用到的鏡頭模板，只能是鏡頭表裡有的）。
- `cut.md`：給 Claude 讀的規則，分「腳本」「鏡頭順序」「相鄰兩幕要不一樣」「拍數」幾節。
- `thumb.png`：面板剪法卡上的縮圖（320×180）。用 `sample/storyboard.json` 跑 `frames.mjs`，風格用「從素材定義風格」的範本（`align: "left"` 才是實際的大字），挑最能代表這種剪法的一格；直式剪法挑三格並排。

| id | 名稱 | 適合 |
|---|---|---|
| `fast-tour` | 快節奏導覽 | 有網站可截圖的產品、作品集；README 的 12–20 秒動圖 |
| `walkthrough` | 操作示範 | 有操作流程的網站或工具（搜尋、切換、一鍵複製）；示範「怎麼用」的 20–25 秒影片，16:9 |
| `signature` | 招牌片（生成式） | 發表會、演講開場、社群上的品牌招牌片；不需要常常改版的一支片 |

一般剪法只能組合現有的鏡頭模板，不寫新的動畫程式；同一份分鏡表永遠算出同一支片。

**生成式剪法**（`"mode": "generate"`，目前只有 `signature`）是例外：`shots` 是空的，改附一份 `kit.html` 骨架，由 Claude 每次從零寫一份 `reel.html`。概念與畫面每次不同；鎖住的是腳本（畫面上只能出現 script.md 的字），定稿後的 `reel.html` 重算永遠是同一支片。`cut.md` 改分「腳本」「概念」「逐拍」「做法」「檢查與修改」幾節。

## 內建風格

① 不提供內建風格，外觀一律從素材取色。內建風格只在使用者在對話裡指名要用時才用（例如「換成霓虹」），或做多種風格的合輯（`reel.mjs`）時用：

| id | 名稱 | 適合 |
|---|---|---|
| `screenplay` | 紙卡劇本 | 深藍桌面上的劇本紙、黃色螢光筆。說故事、活動預告 |
| `studio` | 暖白解說 | 米白底、珊瑚橘重點、圓角卡片。產品介紹、教學、一般大眾 |
| `terminal` | 終端機 | 黑底綠字、掃描線、逐字跳出。開發工具、CLI、技術分享 |
| `neon` | 霓虹 | 深紫夜色、發光洋紅、側滑轉場。活動、遊戲、舞台感開場 |
| `blueprint` | 藍圖 | 工程藍底、白色格線。架構、流程、系統類主題 |

## 分鏡表格式

```json
{
  "title": "影片標題（結果頁用）",
  "cut": "fast-tour",
  "aspect": "9:16",
  "url": "https://example.com",
  "beat": 0.4,
  "scenes": [
    { "shot": "hook", "heading": "**看的人得到什麼**\n一句話。" },
    { "shot": "intro", "kicker": "小標", "heading": "產品或人名", "image": "home-dark-full.png", "to": "首頁上第二段的標題" },
    { "shot": "card", "label": "01 / AI", "icon": "◈", "year": "2026", "kicker": "01 / AI・2026", "heading": "作品一" },
    { "shot": "card", "label": "02 / WEB", "icon": "✚", "year": "2026", "kicker": "02 / WEB・2026", "heading": "作品二" },
    { "shot": "toggle", "pill": "☾ 深色 ／ 淺色 ☀", "heading": "切換前後的那一句", "image": "home-dark-full.png", "after": "home-full.png" },
    { "shot": "feature", "kicker": "作品一", "heading": "這個作品\n**做了什麼**", "tags": ["技術", "技術", "技術"], "image": "project-full.png", "to": "作品頁上的某段標題" },
    { "shot": "content", "heading": "內容頁的\n**那一句**", "image": "articles-full.png", "to": "文章頁上的某個標題" },
    { "shot": "cta", "heading": "號召行動\n**那一句**", "image": "home-full.png", "to": "聯絡區的標題" },
    { "shot": "outro", "kicker": "小標", "heading": "名字或產品名", "sub": "一行說明" }
  ]
}
```

- `aspect`：`16:9`（預設）、`9:16`（直式短影音）、`1:1`。`beat`：一拍幾秒，預設 0.4。
- 每一幕寫 `shot` 與模板要的欄位（見 ③ 的表）；`beats` 或 `seconds` 不寫就用模板預設。
- `image`、`after` 的路徑相對於分鏡表所在的資料夾，用 capture.mjs 產生的檔名（`.png`；範例轉成 `.jpg` 只是為了讓 repo 小一點）；旁邊同名的 `.json` 是錨點檔。

**舊的低階幕別**（素材不是網站時用；不寫 `shot`、改寫 `kind` 與 `seconds`）：

```json
{ "kind": "browser", "seconds": 4, "address": "example.com", "image": "shot-1.png",
  "focus": [{ "at": 0, "x": 0.5, "y": 0.5, "zoom": 1 }, { "at": 0.6, "x": 0.3, "y": 0.4, "zoom": 1.6 }],
  "clicks": [{ "at": 0.4, "x": 0.3, "y": 0.4 }], "caption": "字幕" }
{ "kind": "terminal", "seconds": 4, "name": "Claude Code", "lines": ["會逐字打出來的指令", { "type": "out", "text": "輸出", "highlight": true }] }
{ "kind": "file", "seconds": 3, "name": "style.md", "lines": ["一行", { "text": "要標亮的一行", "highlight": true }] }
{ "kind": "points", "seconds": 3, "heading": "三個重點", "items": ["一", "二", "三"] }
{ "kind": "title" | "outro" | "phone" | "card", ... }
```

- 低階幕別都可以加 `caption`（字幕）、`step`（上方標籤）、`tone`、`transition`（`cut`、`fade`、`slide`、`blur`、`wipe`、`push`、`zoom`、`flash`、`iris`）。
- `focus`、`clicks` 的 `at` 是這一幕的進度（0–1），`x`、`y` 是圖片上的位置比例。

**操作示範的鏡頭模板**（`reveal`、`home`、`seek`、`burst`、`click`、`expand`、`focus`、`dock`）在 `scripts/walkthrough.mjs`，各自展開成下面的 `page` 幕；怎麼排、各寫哪些欄位看操作示範剪法的 `cut.md`。這些鏡頭不套快節奏的規則（一個鏡頭最長 3 秒、平均 1–1.8 秒），檢查是 `page` 幕自己的（運鏡、點擊、螢光筆、按按鈕）。

**網頁鋪滿畫面＋攝影機**（`page`，操作示範剪法的底層；截圖要用新版 `capture.mjs --full`，錨點檔要有頁面寬高與 `box`）：

```json
{ "kind": "page", "seconds": 6, "image": "step-1-full.png",
  "camera": [{ "at": 1, "dur": 1, "to": "切換城市", "zoom": 2.5 }, { "at": 2.5, "dur": 1.5, "to": "24 小時預報", "zoom": 1.6 }] }
```

- `camera` 的 `at`、`dur` 是秒（這一幕自己的時間）；`to` 寫截圖上的字（對到錨點的中心），或改寫 `x`、`y`（截圖寬高的比例）；`zoom` 1 是截圖的寬塞滿畫面，最多 4。`to` 也可以寫成陣列（`["日出與日落", "複製連結"]`）：幾段字一起入鏡，縮放自動限制在放得下的大小（四周留 15%）。
- `page` 幕可以寫 `caption`：左下角的大字卡（操作示範的 `home` 用它放標語前半）。
- **同一時間只有一種運鏡**：兩個運鏡時間重疊會擋下來；方向相反（推近接拉遠）中間要隔半拍，不然會提醒。運鏡之間的空檔自動慢慢推近（每秒 1.5%），不會完全靜止。
- 攝影機會夾在截圖範圍內，不會露出截圖外的空白；目標靠邊時攝影機停在邊緣，推近後目標不在畫面裡才會提醒。
- 前一幕也是 `page` 時，攝影機從前一幕的最後一格接著走（一鏡到底），預設硬切：同一個位置換一張截圖。要重新開始就寫 `start`（跟運鏡一樣寫 `to` 或 `x`、`y`，加 `zoom`）。
- **游標與點擊**：`"clicks": [{ "at": 2.75, "to": "切換城市" }]`，`at` 是按下去的那一刻（秒）。游標自己提早移過去、停 1 拍再按，按下去時縮一下、冒出重點色光圈。游標貼在網頁上，攝影機推近時跟著內容走；前一幕也是 `page` 時游標接著用（畫面上的位置不變），寫 `"cursor": false` 收起來。操作示範的做法是：這一幕點下去，下一幕換成 `capture.mjs --click` 截的「點了之後」那張。
- 點擊會提醒的：兩次點擊太近（游標來不及移過去再停 1 拍）、按下去時攝影機正在運鏡、按下去時目標不在畫面裡。
- **按按鈕（按鈕狀態變化）**：`"presses": [{ "at": 2.5, "to": "複製連結", "after": "after-full.png", "afterTo": "已複製" }]`。先用 `capture.mjs --full --click "複製連結" --name after` 截一張按了之後的；按下去那一刻（也算一次點擊，游標會移過去、冒光圈）只把按鈕那一塊換成 after 截圖上的同一塊，畫面其他地方不動（兩次截圖之間即時資料會變，整張換會連別的地方一起跳）。`afterTo` 是按了之後按鈕上的字，按鈕變寬或移位時用來對位置，不寫就用同一個位置。按了之後那一塊看起來跟按之前一樣時會提醒（多半是 after 截錯了）。
- **螢光筆**：`"marks": [{ "at": 1.9, "to": "現在天氣" }]`，從 `at` 起 0.4 秒（`dur` 可改）從左到右劃過那段字，劃完留到這一幕結束；貼在網頁上，推近時跟著放大。淺底整段蓋過去，深底（深色卡片上的白字）自動改成字底下一條粗底線，也可以寫 `"style": "fill"` 或 `"under"` 指定。劃的時候攝影機在動、劃完那段字不在畫面裡、劃完停不夠讀完（每字 0.06 秒，至少 0.5 秒）都會提醒。

## 風格檔格式

```json
{
  "id": "my-brand",
  "name": "品牌風格",
  "description": "一句話描述氣氛",
  "colors": { "bg": "#fff", "surface": "#fff", "text": "#111", "muted": "#666",
              "accent": "#e2694a", "accentText": "#fff", "border": "#ddd",
              "accentInk": "（選填）accent 當文字用時的顏色", "backdrop": "（選填，paper 裝飾的桌面色）" },
  "fonts": { "display": "標題字體", "body": "內文字體", "mono": "等寬字體" },
  "radius": 12,
  "shadow": "CSS box-shadow，或 none",
  "motion": { "enter": "rise | pop | step | blur", "heading": "（選填）標題的進場，同 enter", "duration": 0.4,
              "transition": "fade | cut | slide | blur | wipe | push | zoom | flash | iris" },
  "decor": "none | paper | scanlines | grid | glow | halo",
  "caption": "plain | bar | highlight",
  "mark": "box | ink（選填，重點字畫色塊或只換字色，預設 box）",
  "align": "center | left（選填，title／outro 的版面，預設 center）",
  "progress": "true | false（選填，底部進度條，預設 true）",
  "fontUrl": "（選填）Google Fonts 的 CSS 網址，算圖時會先下載"
}
```

`colors` 也可以加 `invertBg`：`tone: "invert"` 幕的底色，沒寫時用 `text`。

字體清單一定要以中文字體收尾（例如 `"PingFang TC", "Noto Sans TC", sans-serif`），否則中文會退回系統預設字體。
